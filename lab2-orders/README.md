## Запуск

Требуется Python 3.10 или новее. Распакуйте весь архив. В терминале перейдите в `project/`:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

macOS / Linux:

```bash
source .venv/bin/activate
```

Далее:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Откройте http://127.0.0.1:8000/ . Оплаченные заказы: http://127.0.0.1:8000/?paid=1 .

В архив включена демонстрационная база с тремя вымышленными заказчиками. При запуске с новой базой загрузите данные:

```bash
python manage.py loaddata demo_orders
```

Фикстура использует ID 1–3; повторная загрузка перезаписывает эти демонстрационные записи. Не загружайте её в базу с собственными данными под этими ID.

## CRUD и миграции

```bash
python manage.py showmigrations orders
python manage.py sqlmigrate orders 0001
python manage.py sqlmigrate orders 0002
python manage.py shell
```

В интерактивной консоли выполните:

```python
exec(open('demo_crud.py', encoding='utf-8').read())
```

Сценарий выполняет все CRUD-операции и откатывает только свои демонстрационные изменения через транзакцию. Имеющиеся записи сохраняются.

Для изучения базы в SQLiteStudio откройте `project/db.sqlite3`, таблицу `orders_order`. Исходная модель создана миграцией `0001_initial`, адрес добавлен отдельной миграцией `0002_add_delivery_address`.

## Административная панель

```bash
python manage.py createsuperuser
```

Создайте собственные имя и пароль, затем откройте http://127.0.0.1:8000/admin/ . Готовые пароли и суперпользователь в архив не включены. В админке доступны создание, просмотр, изменение, удаление, поиск и фильтрация заказов.

## Проверки

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test orders -v 2
```

Все шесть тестов проверяют фильтрацию, сохранение суммы и оплаты, удаление, валидацию, страницу оплаченных заказов и защиту административной панели.

## Настройки

Учебный проект работает локально с `DEBUG=True`. Значение `SECRET_KEY` по умолчанию обозначено как учебное; для размещения сервера задайте собственный `DJANGO_SECRET_KEY` через переменную окружения и настройте `DEBUG` и `ALLOWED_HOSTS`.

Модель Order не содержит изображений: `MEDIA_ROOT`, `MEDIA_URL` и Pillow для варианта 10 не требуются. Публичная страница предназначена для просмотра демонстрационных данных. Изменение записей через веб-интерфейс требует входа в админку.

Проект написан на Django согласно заданию № 2 и не зависит от Flask-проекта из предыдущего архива.
